## 8. Computational grammar

The current working grammar preserves distinct operations and comparisons:

```text
gets
→ assignment / reception / transformation result

==
→ equality under a declared comparison

===
→ exact equality under a declared comparison
```

Preserve:

```text
ASSIGNMENT
≠ COMPARISON
≠ EXACT COMPARISON
≠ RELATION
```

Example:

```text
observed_hash gets hash(observed_object)

observed_hash === expected_hash
              [SHA-256 / declared comparison domain]
```

`===` establishes exact equality only under the declared comparison domain. It does not establish universal identity.

```text
A === B
[under comparison C]

≠

A and B are ontologically identical
```

The breadth of `gets` remains open. Where used, the local operation should be named.

```text
observed_hash gets hash(observed_object)
use: transformation result
```

or:

```text
carrier gets received_object
use: reception
```

Do not let a single token silently erase the operation being performed.

## 9. Distinct I/O operations

Permission and operation type must remain distinguishable.

> **Permission is action-local.**

But the deeper computational distinction is operational:

```text
READ
≠ WRITE

CREATE
≠ UPDATE

UPDATE
≠ MOVE

MOVE
≠ DELETE

DELETE
≠ SHARE
```

More specifically:

```text
CREATE
→ adds a new object / state

DELETE
→ removes an existing object / state
```

A provider may bundle several operations under one technical permission surface. That bundling does not make those operations identical.

Therefore prefer:

```text
operation gets CREATE
```

over a coarse formulation such as:

```text
access gets WRITE
```

when the actual operation is creation.

Operational identity and permission scope are adjacent but distinct:

```text
OPERATION TYPE
≠ PROVIDER PERMISSION BUNDLE
≠ FOUNDER AUTHORIZATION
```

Action-local boundaries:

```text
PERMISSION TO CREATE
≠ PERMISSION TO DELETE
≠ PERMISSION TO MOVE
≠ PERMISSION TO RENAME
≠ PERMISSION TO OVERWRITE
≠ PERMISSION TO SHARE
≠ PERMISSION TO ALTER EXISTING CONTENT
```

Access does not silently become authority.

```text

```

### Exact passage

Candidate computational form:

```text
hex_form gets encode(character)
returned_character gets decode(hex_form)

returned_character === character
                   [Unicode code-point domain]
```

The interface performs an operation. It does not equal fidelity.

```text
INVERSION OPERATION
≠ REPRESENTATIONAL FIDELITY
```

Fidelity is examined separately.

### No silent synonym normalization

Do not silently normalize:

```text
~
≈
\cong
~=
=~
```

into:

```text
&#x2245;
```

Visual similarity or semantic nearness does not establish admissible substitution.

```text
VISUAL SIMILARITY
≠ TOKEN IDENTITY

SEMANTIC NEARNESS
≠ ADMISSIBLE SUBSTITUTION

TRANSLATION
≠ SUBSTITUTION
```

### Comparison layers

Preserve:

```text
CODE-POINT EXACTNESS
≠ SERIALIZATION EXACTNESS
≠ BYTE EXACTNESS
```

For example, multiple character references may resolve to the same code point while remaining different serializations.

The declared comparison domain must determine what `===` means in each case.

## 12. State verification

```text

```

Candidate pattern:

```text
expected_hash gets declared_expected_hash
```

```text

standing

legal conclusion
```

```text
MISMATCH
NOT CHECKED
```

These results are not interchangeable.
